# TEXT モードの SIO（Save / Load）

`TEXT` キー → `Sio` → `Save` / `Load` で、テキストエディタの内容を外部へ出し入れできる。
本ドキュメントはその経路を実測で確かめた記録である。

**これは実機がどうなっているかの記録であり、エミュレータへの実装は
[../emulator/text-sio-file-io.md](../emulator/text-sio-file-io.md) に分けてある。**

## 結論: ハードウェア UART は使わない

名前が「SIO」で `Format` 画面にボーレートやパリティの設定があるため、
[11pin-uart.md](11pin-uart.md) に書かれたハードウェア UART（`0x70`-`0x74`）を
使っていると推測していたが、**これは誤りだった。**

実測すると、`Save` でも `Load` でも UART のポートは **1 回も**触られない。
`BSAVE` と同じ **ポート `0x18` の bit7（XOUT）と `0x1F` の bit2（XIN）を
ソフトウェアで叩く**方式で、違いは変調方式だけである。

| | 変調 | 出力 | 入力 |
|:--|:--|:--|:--|
| `BSAVE` / `BLOAD` | PWM（H 期間の長さでビットを表す）| `0x18` bit7 | `0x1F` bit2 |
| TEXT の SIO | **調歩同期（非同期シリアル）** | `0x18` bit7 | `0x1F` bit2 |
| RS-232C | ハードウェア UART | `0x72` | `0x72` |

`0x60`（11pin の動作モード）も SIO では書かれない。`BSAVE` は書く。

## Format 画面の設定項目

`TEXT` → `Sio` → `Format` で表示される。項目は 8 つあり、画面には 6 行ずつ出る。
工場出荷時の値は次のとおり。

| 項目 | 既定値 | 備考 |
|:--|:--|:--|
| baud rate | 1200 | 1200 / 2400 / 4800 / 9600。両端でクランプし、巡回しない |
| data bit | 8 | |
| stop bit | 1 | |
| parity | none | |
| end of line | CR LF | |
| end of file | 1A | |
| line number | yes | BASIC の行番号を含めて送受信する |
| flow | RS/CS | フロー制御。後述の `0x1F` bit1 はこれに対応すると思われる |

カーソルは `←` `→` `↑` `↓` で移動し、`↵` で確定する。

**`↵` で各項目を確定していかないと変更は反映されない。** 値を変えただけで
`TEXT` キーを押して抜けると、元の設定のままになる。

## 実測（2026-08-30）

`z80inport` / `z80outport` をフックしてポートアクセスを記録した。

### アクセスされたポート

`Save` でも `Load` でも、触られる 11pin 関連のポートは次の 3 つだけだった。

| ポート | 向き | 内容 |
|:--|:--|:--|
| `0x15` | 出力 | 開始時に **`0x80` を 1 回**だけ書く |
| `0x18` | 出力 | `Save` では bit1 を立てて bit7 にデータを乗せる。`Load` では 3 回だけ（`0x00` `0x02` `0x03`）|
| `0x1F` | 入力 | `Save` は送信可否の待ち合わせ、`Load` はデータの読み取り |

**`0x60` および `0x70`-`0x74` へのアクセスは 0 回。** これが UART を使っていない根拠。
なお `0x19` / `0x69`（ROM バンク）と `0x40` / `0x41`（LCD）は常時アクセスされるので
SIO とは無関係である。

`0x15` は [11pin-uart.md](11pin-uart.md) で「Xin 入力イネーブル。どのビットが
何を有効にするかは不明」としていたポートで、`Save` / `Load` のどちらでも
開始時に `0x80` が書かれる。

## 送信（Save）

### フレーム形式

`0x18` への書き込みのうち **bit1 が 1 のとき**が SIO の送出で、
そのときの bit7 がデータビットになる。**bit7 は論理値の反転**（bit7 = 1 でデータ 0）。

```
アイドル/ストップ = 1
スタートビット    = 0
データ 8 ビット   = LSB ファースト
```

`Format` 画面の既定値（データ 8 ビット、ストップ 1 ビット、パリティなし）と一致する。

ROM は **1 ビットにつき 1 回**書くので、書き込みを数えればビットが取れる。

### ビット周期とボーレート

bit7 の変化点の間隔を Z80 のステート数で測った。**設定に比例して変わる。**

| `Format` の設定 | ビット周期 | エミュレータ（9000 kHz）| 実機（8 MHz と仮定）|
|:--|--:|--:|--:|
| 1200 baud | 6733 ステート | 748.1 usec (1337 baud) | 841.6 usec (**1188 baud**) |
| 9600 baud | 822 ステート | 91.3 usec (10949 baud) | 102.8 usec (**9732 baud**) |

実機のクロックで計算すると設定値と 1〜2% 以内で一致する。
この 9/8 のずれは `BSAVE` の PWM で観測したものと同じで、
エミュレータのクロックが実機より約 11% 速いことの表れである
（[bsave-signal-format.md](bsave-signal-format.md) 参照）。

ソフトウェアでビットを叩いている以上、ボーレートは CPU クロックに直結する。
**受信側（`Load`）へ信号を送るときは、この設定に合わせた周期でなければ復号されない。**

### 送信前の待ち合わせ

**ROM は `0x1F` の bit1 が 1 になるまで送信を始めない。**

bit1 が 0 のままだと画面は `--- SENDING ---` を表示したまま止まり、
`0x1F` をひたすら読み続ける。実測では 3800 万ステート（実機で約 4.8 秒）の間に
**126 万回**読んでいた。約 30 ステートに 1 回の密なポーリングである。

bit1 を 1 にすると送信が始まり、`0x18` への書き込みが現れる。
`Format` の `flow` が `RS/CS` であることから、これは **CS（CTS）に相当する
受け側の準備完了**と考えられるが、11pin のどのピンかは確かめていない。

### 得られるバイト列

工場出荷時の設定で `10 ABCDE` の 1 行を送ると、次の 11 バイトになる。

```
31 30 20 41 42 43 44 45 0d 0a 1a
 1  0     A  B  C  D  E CR LF EOF
```

`line number = yes` なので行番号 `10` が含まれる。行末の CR LF と終端の `0x1A` も
`Format` の設定どおりに付く。

## 受信（Load）

`Load` を選ぶと画面が `--- RECEIVING ---` になり、`0x1F` を
**約 25 ステートに 1 回**読み続ける（2730 万ステートで 108 万回）。

### 読んでいるビットと極性

**`0x1F` の bit2。`BLOAD` と同じ XIN のピンである。**

極性は出力と同じく**反転**している。

| ポートのビット | 論理値 |
|:--|:--|
| 0 | 1（アイドル / ストップビット）|
| 1 | 0（スタートビット / データの 0）|

エミュレータは `0x1F` の未実装ビットを 0 で返すため、ROM から見ると
常にアイドルに見えている。だから `--- RECEIVING ---` のまま待ち続ける。

**`Load` に bit1 は要らない。** bit1 を 0 のままにして bit2 だけを振ったところ
正しく受信できた。bit1 は送信側だけの待ち合わせである。

### フレーム形式

送信側と同じ。1 バイトはスタートビット（0）、データ 8 ビット（LSB から）、
ストップビット（1）の 10 ビット。ビット周期は `Format` の設定に従う。

終端コード（既定 `0x1A`）を受け取ると受信を終えてメニューへ戻る。
終端が来なければ待ち続ける。

### 確認したこと

エミュレータ側で bit2 に上記の波形を流し込んで確かめた。

- 1200 baud 設定・6733 ステート/ビットで `10 AB` CR LF EOF を送り、
  テキストエディタに `10 AB` が入ることを確認
- 9600 baud 設定・822 ステート/ビットでも同様に成功。
  **設定を変えたら送出側の周期も変えなければならない**
- 送ったものをそのまま `Save` で読み出すと、送ったバイト列と 1 バイトも違わずに戻る

エディタの内容は `Edit` に入って `L`（LIST）で確認できる。

- `end of line` / `end of file` を変えたときに送出データが変わるか
  （既定値の CR LF と `0x1A` がそのまま出ることは確認済み）

- `data bit` や `parity` を変えたときのフレーム形式
- `0x15` の `0x80` が具体的に何を有効にしているか
- `0x18` bit1 の役割（SIO のイネーブルなのか、別の意味があるのか）と、
  `Load` の開始時に書かれる `0x03` の bit0 の意味
