# 11pin インターフェースと UART の I/O ポート

PC-G850 系の 11pin インターフェース周辺の I/O ポートについて。

## 出典

- **PC-G850V UART I/O ポート** — https://ver0.sakura.ne.jp/doc/pcg850vuart.html
- **ポケコン PC-G850 の解析とソフト集 [I/O編]** — http://park19.wakwak.com/~gadget_factory/factory/pokecom/io.html

  この資料は **PC-G850V 向け**であり、PC-G850 / PC-G850S とはポート配置が異なる。
  資料自身が「独自に解析したもののため正確ではないかもしれない」と断っている点に注意。
  以下の**ビット定義はこの資料に基づく記述**で、本プロジェクトで実測して確かめたものではない。

## 11pin インターフェースの 2 つの使い方

11pin インターフェースは用途によって全く違う経路を通る。混同しないこと。

| 用途 | 経路 | ポート |
|:--|:--|:--|
| カセット互換の転送（`BSAVE` / `BLOAD` / `SAVE` / `LOAD`）| **ソフトウェアによる PWM のビットバンギング**。UART は使わない | 出力 `0x18` の bit7（XOUT）、入力 `0x1F` の bit2（XIN）|
| RS-232C 通信 | **ハードウェア UART** | `0x60` `0x63` `0x70`-`0x74`（G850V）|

PWM 側の詳細は [bsave-signal-format.md](bsave-signal-format.md) を参照。

## ポート一覧（PC-G850V）

| アドレス | 入出力 | 内容 | PC-G850 での対応 |
|:--|:--|:--|:--|
| `60H` | 出力 | 11Pin I/F の設定 | PC-G850 と同じ |
| `63H` | 入出力 | UART のフロー制御レジスタ | PC-G850 と同じ |
| `6CH` | - | 不明 | PC-G850 では UART モードレジスタ |
| `6DH` | - | 不明 | PC-G850 では UART コマンドレジスタ |
| `6EH` | - | 不明 | PC-G850 では UART ステータスレジスタ |
| `6FH` | - | 不明 | PC-G850 では UART 送受信レジスタ |
| `70H` | 出力 | UART モードレジスタ（ボーレート・割り込み）| `6CH` に相当 |
| `71H` | 出力 | UART モードレジスタ（パリティ・データビット長）／UART コマンドレジスタ | `6CH` / `6DH` に相当 |
| `71H` | 入力 | UART ステータスレジスタ | `6EH` に相当 |
| `72H` | 入出力 | UART 送受信レジスタ | `6FH` に相当 |
| `73H` | 出力 | UART ハードウェアリセット | - |
| `74H` | 出力 | UART クロックイネーブル | - |

`71H` は出力が 2 種類の意味を持つ。b1=1 かつ b0=0 ならモードレジスタ、そうでなければ
コマンドレジスタとして解釈されると思われる。

## レジスタのビット定義

### 70H（出力）UART モードレジスタ

```
b7 b6 b5 : 0
b4 b3    : 割り込み
b2 b1 b0 : ボーレート
```

| ボーレート | 値 |
|:--|:--|
| `000` | 300 baud |
| `001` | 600 baud |
| `010` | 1200 baud |
| `011` | 2400 baud |
| `100` | 4800 baud |
| `101` | 9600 baud |
| `110` `111` | N/A |

| 割り込み | 値 |
|:--|:--|
| `00` | 割り込み不許可 |
| `01` | 受信割り込み許可 |
| `10` | 送信割り込み許可 |
| `11` | N/A |

### 71H（出力）UART モードレジスタ

```
b7    : 0
b6    : 1
b5 b4 : パリティ
b3 b2 : データビット長
b1    : 1
b0    : 0
```

| データビット長 | 値 |
|:--|:--|
| `00` | 小文字に変換？ |
| `01` | 大文字に変換？ |
| `10` | 7bit |
| `11` | 8bit |

| パリティ | 値 |
|:--|:--|
| `00` | パリティなし |
| `01` | 奇数パリティ |
| `10` | 偶数パリティ |
| `11` | N/A |

### 71H（出力）UART コマンドレジスタ

```
b7 : 0
b6 : ソフトウェアリセット（1 = SIO をリセット）
b5 : 0
b4 : エラーフラグクリア（1 = エラーをクリア）
b3 : 0
b2 : 受信イネーブル（1 = 受信可能）
b1 : 0
b0 : 送信イネーブル（1 = 送信可能）
```

### 71H（入力）UART ステータスレジスタ

```
b7 b6 : 0
b5    : フレーミングエラー
b4    : 受信オーバーランエラー
b3    : パリティエラー
b2    : 送信データエンプティ？
b1    : 受信データレディ（1 = 受信待ちデータあり）
b0    : 送信データエンプティ？
```

### 72H（入出力）UART 送受信レジスタ

b7-b0 が送受信データ。

### 73H（出力）UART ハードウェアリセット

b0 のみ。**1 のままだと送受信できない。`0` → `1` → `0` と出力すること。**

### 74H（出力）UART クロックイネーブル

b0 のみ。**1 にしないと送受信できない。**

## 初期化の手順（資料のサンプル）

9600baud、8bit、パリティなしの例。

```basic
110 OUT &H60,2    'UART モード
120 OUT &H74,1    'クロックイネーブル
130 OUT &H73,0    '|
140 OUT &H73,1    '+ ハードウェアリセット
150 OUT &H73,0    '|
160 OUT &H70,&HD  '9600baud, 受信割り込み
170 OUT &H71,&H4E 'SIO リセット, パリティなし, 8bit
180 OUT &H71,&H10 'エラークリア
190 OUT &H63,0    'フロークリア
```

送受信はステータス `INP(&H71)` を見て、`INP(&H72)` / `OUT &H72,x` でデータをやり取りする。

比較用に、PC-G850（無印）では同じことを `6CH`-`6FH` で行う。

```basic
110 OUT &H60,2      'UART モード
120 OUT &H6D,&H80   'SIO リセット
130 OUT &H6D,&H40   'エラークリア
140 OUT &H63,0      'フロークリア
150 OUT &H6C,&H0D   '9600baud, 受信割り込み, パリティなし
160 OUT &H6D,&H30   '送受信イネーブル
170 OUT &H63,&H14   'DR, RS ON
```

## 11pin の動作モード（60H）

11pin インターフェースは 3 つのモードを持ち、`60H` の下位 2 ビットで選ぶ。

| D1 D0 | 動作 |
|:--|:--|
| `00` | 従来の 3-In 3-Out I/F（カセット互換。`BSAVE` / `BLOAD` はこれ）|
| `01` | 8bit PIO（`61H` で方向、`62H` でデータ）|
| `10` | 全二重通信の出来る UART |
| `11` | N/A |

## Xin 入力イネーブル（15H）

`1FH` で読める Xin（11pin の入力）は、**`15H` で入力可能にしておかないと入力できない**
（0=入力禁止、1=入力可能）。

エミュレータは `15H` を未対応にしているため、実際には `15H` の状態に関係なく `in1f()` の値が
そのまま読める。本プロジェクトで追加した BLOAD の送出もこの状態に依存していない。
実機に忠実にするなら `15H` の値で Xin をゲートすべきだが、どのビットが有効化なのかが
資料の図からは読み取れていないため、現状は実装していない。

## 実測: BSAVE / BLOAD が行う 11pin の初期化（2026-08-30）

`BSAVE` と `BLOAD` の実行直後に、11pin と UART 関連のポートへどう書き込むかを記録した。

### BSAVE

```
IN  60 -> 00      現在の 11pin モードを読む
OUT 60 =  00      11pin を「従来の 3-In 3-Out I/F」に設定
IN  15 -> 00
OUT 15 =  00      Xin 入力を禁止（送信のみなので入力は不要）
OUT 74 =  01      UART クロックイネーブル ON
OUT 73 =  00  \
OUT 73 =  01   >  UART ハードウェアリセット（0 → 1 → 0）
OUT 73 =  00  /
OUT 74 =  00      UART クロックイネーブル OFF
```

### BLOAD

```
（BSAVE と全く同じ 9 手順）
IN  15 -> 00
OUT 15 =  90      ★ Xin 入力を有効化
```

**BSAVE と BLOAD の初期化は同一で、BLOAD だけ最後に `OUT 15H,90H` が付く。**
これが Xin の入力可能設定にあたる。

読み取れること:

- `BSAVE` / `BLOAD` は 11pin を **UART モードではなく従来の 3-In 3-Out モード**で使う。
  データは PWM のビットバンギングで直接作られる。
- その前に **UART を明示的にリセットして停止**している
  （クロックを入れてハードウェアリセットをかけ、またクロックを切る）。
  UART がピンを駆動しないようにするためと思われる。
- 資料にある UART の初期化手順 `OUT &H74,1` → `OUT &H73,0/1/0` と完全に一致する。
  `0x73` への書き込みが 3 回なのはリセットが `0 → 1 → 0` の 3 手順だから。

**注意**: エミュレータは `60H` と `15H` を未対応にしており `IN` は 0 を返す。ROM が
リード・モディファイ・ライトをしている場合、実機なら保存されるはずの他ビットが
0 として書き戻されている可能性がある。上記の書き込み値はその前提で読むこと。

## 搭載 ROM は PC-G850V と考えられる

`0x70`-`0x74` は PC-G850V 固有のポートで、PC-G850（無印）なら `6CH`-`6FH` を使うはずである。
実機から吸い出した ROM がこれらを叩いている以上、**PC-G850V** の ROM と判断してよい。

## エミュレータでの実装状況

**UART は一切実装されていない。**

- `0x60`-`0x6F` は `in60_g850()` / `out60_g850()` のような関数が用意されているが、
  中身はすべて `/* 未対応 */` で、読み出しは 0 を返し書き込みは捨てられる。
  `in6e_g850()` には `//return 0x08; // 08 = UART TX RDY` というコメントアウトが残っている。
- `0x70`-`0x74` は `z80inport` / `z80outport` のディスパッチに存在しない。
  **読み出しは一律 `0x78`、書き込みは捨てられる**（`z80inport` 末尾の `return 0x78`）。

したがって現状 RS-232C による通信はエミュレートできない。

## 今後の可能性

UART を実装すれば RS-232C 経由の通信をエミュレートできる。
PWM の転送は 1 回で 20 秒以上かかるのに対し、9600baud なら桁違いに速いため、
`BSAVE` / `BLOAD` に代わるファイルの出し入れ経路として使える可能性がある。
