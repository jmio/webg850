# 実装計画: BSAVE / BLOAD の相手をファイルと実機から選べるようにする

作成日: 2026-08-30
状態: **完了**（2026-08-30）

## 目的

エミュレータの `BSAVE` の出力先と `BLOAD` の入力元を、**ファイル**と
**Web Serial 経由の実機**から選べるようにする。

実機との橋渡しは [arduino-11pin/](../../arduino-11pin/) で確立済みで、
Arduino Uno R4 Minima 経由で実機の 11pin I/O に対して 2854 バイトの往復が
バイト単位で一致することを確認してある。本計画はその成果をブラウザから
直接使えるようにするもの。

## ゴール（完了条件）

1. `BSAVE 先` を「ファイル」「実機」から選べる
2. `BLOAD 元` を「ファイル」「実機」から選べる
3. 実機を選んだとき、エミュレータの BASIC プログラムが実機へ渡り、
   実機の BASIC プログラムがエミュレータへ戻る
4. 進捗が画面に出る（転送に 20〜40 秒かかるため必須）
5. **Web Serial が使えない環境でも従来どおり動く**（実機の選択肢を出さない）

## 用語の注意（混乱しやすい）

「BSAVE 先 = 実機」のとき、**実機側で実行するのは `BLOAD`** である。
エミュレータが「保存」する先が実機なので、実機は「読み込む」側になる。

| 画面上の選択 | エミュレータで実行 | 実機で実行 | 波形の向き |
|:--|:--|:--|:--|
| BSAVE 先 = ファイル | `BSAVE` | — | — |
| **BSAVE 先 = 実機** | `BSAVE` | **`BLOAD`** | Arduino → 実機 |
| BLOAD 元 = ファイル | `BLOAD` | — | — |
| **BLOAD 元 = 実機** | `BLOAD` | **`BSAVE`** | 実機 → Arduino |

UI の文言はこの取り違えを防ぐことを最優先にする。

## 実験から持ち込む前提（すべて実機で確認済み）

詳細は [arduino-11pin/docs/experiment-log.md](../../arduino-11pin/docs/experiment-log.md)。

### やり取りの単位は `.bin`

**信号形式の知識をブラウザ側に持ち込む必要は無い。**
エミュレータは既に `.bin` を読み書きできる（`bsaveFinish` / `bloadLoadFile`）。
波形のタイミング・極性・パリティはすべてファームウェアの中にある。
Web Serial 層は **`.bin` を運ぶだけ**でよい。

### プロトコルの性質

| 事項 | 内容 |
|:--|:--|
| 終端 | **`+OK` で始まる行か `!` で始まる行の 2 つだけ** |
| 種別 | `+` データ / `!` エラー(終端) / `#` 情報 / `*` 進捗 |
| 文字 | **ASCII のみ。** 日本語は入らない |
| ボーレート | USB CDC なので実効的に無関係 |
| 中断 | `ESC` (0x1B) か `Ctrl-C` (0x03) を**生の 1 バイト**で送る |

### `LOAD`（ブラウザ → デバイス）

- **フロー制御は要らない。** 12288 バイト（27652 文字・384 行）を
  **1 回の `write` で投げてよい**。`+RDY` を待たなくても通る
- **1 行は 92 バイトまで。** 既定の 32 を変える理由は無い
  （1 行を長くしても 638 → 606 ms でほとんど速くならない。
  律速はデバイス側の行の解釈）
- **行と行の間を 10 秒以上空けない**（`!ERR timeout`）
- **エラーは 1 行で終わる。** デバイスが残りを読み捨てるので、
  `!` を見たらそのまま次のコマンドを送ってよい
- 速度: ASCII 42 KB/s、実データ 19 KB/s

### `CAP`（デバイス → ブラウザ）

- `+D <ブロック> <オフセット> <16進>` が 32 バイトごとに届く
- **ブロック 1 = ヘッダ 48 バイト、ブロック 2 = 本体。
  どちらも末尾 2 バイトはパリティなので落とす**
- `+R` にパリティの照合結果と `fe`（フレーミングエラー）が出る
- **進捗は `bits` を使う。`bytes` ではない。**
  PWM2 のヘッダ 25848 ビットを読み飛ばす **8.4 秒間は 1 バイトも
  復号されない**ので、`bytes` を見ていると止まって見える
- `#cap begin` が転送の開始を示す
- **取り込みは約 40 秒かかり、短縮できない**（実機が本来のヘッダと
  長い PULSES をそのまま出すため）

### `PLAY`（デバイス → 実機）

- 2854 バイトで **17.5 秒**（起動時の既定 `PROFILE FAST`）
- 送出中は `*PLAY <済>/<総数> <%>` が届く

### 待機してから合図する

**取り込みは、待機に入ったことを確認してから利用者に合図する。**
確認せずに合図すると転送の途中から拾い、ヘッダを取り逃がす。
実験でこれを 1 回やって失敗した。`#cap armed` を受け取ってから
「実機で BSAVE を実行してください」を出すこと。

### 別個体では較正が要る

焼き込んである値は 1 台（PC-G850V）の実測値。別の個体では `CAL` から
やり直す。**この計画では扱わない**（`g850ctl.py` で行う）。

## 設計

### モジュール構成

新規ファイルを 2 つ足し、`g800main.js` への変更は最小にする。

```
webserial.js      Web Serial のプロトコル層（G850Link）
realio.js         BSAVE/BLOAD の相手選択と画面まわり
g800main.js       分岐点を 2 か所だけ足す
webg850v.htm      <script> 2 行と UI
```

**`g800main.js` は 115 KB あり、エミュレータ本体である。**
実機連携の都合でここを太らせない。触るのは次の 2 か所だけにする。

1. `bsaveFinish()` の `downloadBinary` の直前に分岐を入れる
2. `bloadLoadFile()` の中身のうち「バイト列 → `bloadBuild`」を関数に
   切り出し、実機側からも呼べるようにする

### プロトコル層 `G850Link`（webserial.js）

```js
class G850Link {
    async connect()                    // requestPort + open + PING で確認
    async disconnect()
    async command(line, opts)          // +OK まで読む。! なら reject
    async load(bytes, onProgress)      // LOAD + D行 + END
    async play(onProgress)             // PLAY
    async capture(onProgress, signal)  // CAP。.bin を返す
    abort()                            // ESC を 1 バイト
}
```

**読み取り**: `port.readable` → `TextDecoderStream` → 行分割の
`TransformStream`。1 行ごとに種別で振り分ける。

**書き込み**: `TextEncoderStream` は**使わない**。中断の `ESC` を生バイトで
送る必要があるので、`port.writable.getWriter()` に対して `TextEncoder` で
手動符号化する。

**接続の確認**: 開いたら `PING` を送り、`+PONG g850-11pin <版>` を確認する。
別のシリアル機器を選んでしまったときに、そこで止められる。
フェーズ 0 で実際に動かして確かめた。

**`getPorts()` を当てにしない**。許可が保存されないので、
接続は常に `requestPort()` から始める。

**注意**: `pipeThrough` はストリームをロックする。切断時に
`reader.cancel()` → `readableStreamClosed.catch()` → `port.close()` の順で
確実に解放しないと、次の接続で失敗する。

### `.bin` の組み立て（受信側）

`CAP` の `+D` 行から `.bin` を作る手順。

1. ブロック番号ごとにオフセット順で連結する
2. **各ブロックの末尾 2 バイト（パリティ）を落とす**
3. ブロック 1 が 48 バイトであることを確かめる
4. ブロック 1 + ブロック 2 を連結して `.bin` にする
5. ヘッダの `0x12` の 16 ビット（リトルエンディアン）とブロック 2 の
   長さが一致することを確かめる

`+R` の `parity ... OK/NG` と `fe=0` も確認し、どれかが崩れていたら
**エミュレータへ流し込まずに中止する**。壊れたデータを BASIC 領域に
書き込むと復旧が面倒になる。


### 操作の流れ

**BSAVE 先 = 実機**

1. 利用者がエミュレータで `BSAVE` を実行 → `bsaveFinish()` が `.bin` を作る
2. 画面に「**実機で `BLOAD` を実行してから [送出] を押してください**」
3. [送出] → `LOAD`（1 秒未満）→ `PLAY`（17.5 秒）
4. `*PLAY` の進捗を表示
5. 完了後「実機の画面右下に `*` が出れば成功」と案内する

**待たせるのは実機側**にする。実機の `BLOAD` は `BREAK` するまで待ち続ける
ので、先に待たせておけば取りこぼしが無い。

**BLOAD 元 = 実機**

1. [取り込み] → `CAP` を送る
2. **`#cap armed` を受け取ってから**「実機で `BSAVE` を実行してください」
3. `#cap begin` で「転送開始」に切り替え、`*CAP` の `bits` で進捗を出す
4. `+OK` で `.bin` を組み立て、パリティを確認
5. `bloadBuild()` に渡して `bloadArmed = true`
6. 「**エミュレータで `BLOAD` を実行してください**」

### 進捗の総ビット数

`*CAP` の `bits` に対する分母は計算できる。

```
PWM1 = 10000 + 40 + 40 + 1 + (48 + 2) x 9 + 1 = 10532
PWM2 = 25848 + 20 + 20 + 1 + (N  + 2) x 9 + 1
```

`N`（本体サイズ）はブロック 1 のヘッダで分かり、**PWM2 が始まる前に
確定する**。それまでは PWM1 の 10532 を分母にする。

### 既知の制限: 送出は 12288 バイトまで

ファームウェアの `.bin` バッファは 12288 バイトで、**RAM の制約から 13824
までしか増やせない**（ヒープ 8 KB とスタック 1 KB が固定）。実機の空き容量は
27286 バイトなので、

- **取り込み（実機 → エミュレータ）は全域に対応**（流す方式のため）
- **送出（エミュレータ → 実機）は 12288 バイトまで**

12288 を超える `.bin` は送出前に弾き、その旨を表示する。

将来の解決策は**送出も流す方式にすること**。ビット間の L 期間が 164 µs あり、
必要な受信速度は毎秒 787 バイトなので、取り込みと同じ理屈で成立するはずである
（未検証）。本計画の範囲外とする。

1. 実機 `BSAVE` → Arduino 取り込み → `g850ctl.py` → `basen.bin`
2. 実機 `BSAVE` → Arduino → **ブラウザ** → `capture.bin`
3. ブラウザ → エミュレータ `BLOAD` → エミュレータ `BSAVE`
4. → ブラウザ → Arduino `LOAD`+`PLAY` → 実機 `NEW` + `BLOAD`
5. 実機 `BSAVE` → Arduino → ブラウザ → `capture(1).bin`

**4 種類の波形生成・復号（実機の ROM、エミュレータの JS、Arduino の送出、
Arduino の取り込み）を経ても 1 バイトも変わらなかった。**
エミュレータと実機ではクロックが 9/8 違う（実機 8.00 MHz、エミュレータの
既定 9000 kHz）が、`.bin` はタイミングに依存しない形式なので影響しない。

## 得られた知見

1. **`.bin` を唯一のやり取りの単位にしたのが効いた。**
   波形の知識をファームウェアに閉じ込めたので、ブラウザ側は 2 ファイル・
   エミュレータ本体の変更は 2 か所で済んだ。
2. **クロックの違いは `.bin` に現れない。** 実機とエミュレータで
   9/8 の差があるが、往復しても内容は変わらない。
3. **`NEW` を挟んで確認する。** 実機の `BLOAD` は上書きなので、
   `NEW` せずに `LIST` が出ても「元から入っていた」可能性が消えない。
4. **既存の経路を必ず確認する。** リファクタした `bloadLoadFile()` と
   分岐を足した `bsaveFinish()` は、実機を使わない側も通しておく。

## 注意

- **`rom.zip` と ROM 由来のデータは扱わない。** 本機能が運ぶのは利用者の
  BASIC プログラムだけ
- **既存の動作を変えない。** `file://` が主環境である。
  サーバを立てるのは実機に接続するときだけに留める
- 実機へ書き込む前に、実機側のプログラムが失われることを利用者に伝える
  （`BLOAD` は上書きする）
- パリティが崩れたデータは**エミュレータへ流し込まない**
