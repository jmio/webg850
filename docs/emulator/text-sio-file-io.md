# TEXT モードの SIO のファイル入出力

`TEXT` → `Sio` → `Save` / `Load` を、ブラウザ経由でファイルとして出し入れする仕組み。

信号そのものの解析結果は [../analysis/text-sio.md](../analysis/text-sio.md) にある。

## 使い方

### 取り出す（Save）

1. デバッグパネルの **SIO CAPTURE** にチェックを入れる
2. `TEXT` キー → `Sio` → `Save`
3. 送出が終わると `text.txt` がダウンロードされる

チェックを入れないと**送信そのものが始まらない**。ROM はポート `0x1F` の bit1 が
1 になるまで待つようになっており、このチェックボックスがそのビットを立てる。
チェックせずに `Save` を実行すると `--- SENDING ---` の表示のまま止まる。

### 書き戻す（Load）

1. デバッグパネルの **LOAD TXT** でファイルを選ぶ
2. `TEXT` キー → `Sio` → `Load`
3. 送出が終わると受信側がメニューへ戻る

`Load` に SIO CAPTURE のチェックは要らない。
エディタの内容は `Edit` に入って `L`（LIST）で確認できる。

**行番号が必要。** `Format` の `line number` が `yes` なので、
`60 FROM FILE` のように行番号から始まる行を並べたファイルにする。

## 仕組み

| 関数 | 役割 |
|:--|:--|
| `sioCapture(x)` | `out18()` から呼ばれる。1 ビットずつ復号してバイト列に積む |
| `sioPoll()` | `run()` から 1 フレームに 1 回。無通信が続いたら転送を閉じる |
| `sioFinish()` | バイト列を `text.txt` として書き出す |
| `sioReset()` | 復号の状態を初期化する |
| `sioLoadFile()` | ファイルを読んでビット列に展開し、送出を予約する |
| `sioSendBuild(bytes)` | バイト列を調歩同期のビット列に展開する |
| `sioSendPoll()` | `in1f()` から呼ばれる。その時刻のビットを返す |
| `sioSendReset()` | 送出を取りやめる |

`in1f()` は次を OR して返す。

```js
return keyBreak | bloadPoll() | sioSendPoll() | (sioEnable ? 0x02: 0x00);
```

`bloadPoll()` と `sioSendPoll()` はどちらも bit2（同じ XIN のピン）を返すが、
同時に動くことはない。

### 復号（Save）

`0x18` への書き込みのうち **bit1 が 1** のものが SIO の送出で、
そのときの bit7 がデータビット（論理値の反転）。ROM は 1 ビットにつき 1 回書くので、
書き込みをそのまま 1 ビットとして数えればよい。

```
未同期 → アイドル(1) を待つ
      → 0 に落ちたらスタートビット
      → 続く 8 ビットを LSB から詰めて 1 バイト
```

### 送出（Load）

バイト列を 1 バイト 10 ビット（スタート 0 ＋ データ 8 ＋ ストップ 1）に展開し、
前後にアイドルを付けたビット列を作る。`in1f()` が呼ばれるたびに
経過ステート数をビット周期で割って何ビット目かを求め、その値を返す。
極性は反転なので、アイドル（論理 1）のときポートのビットは 0 になる。

送出の開始は **ROM のアドレスに依存せずに検出する。** ファイルを読んだ時点では
予約状態にしておき、`0x1F` が 500 ステート未満の間隔で読まれ始めたら
`Load` が待っていると判断して送出を始める。`BLOAD` と同じやり方。

### ビット周期の自動調整

ボーレートは `TEXT` → `Sio` → `Format` で変えられ、**変えるとビット周期も変わる**。
送出側がこれに合っていないと受信側は復号できない。

そこで**取り込みのたびにビット周期を実測して覚えておく**。ROM は 1 ビットにつき
1 回 `0x18` に書くので、書き込みの最小間隔がビット周期になる。
文字と文字の間は 1 ビット以上空くため、最小値だけを見ればよい。

初期値は 1200 baud 相当の 6733 ステート。実測すると次のようになる。

| `Format` の設定 | 実測したビット周期 |
|:--|--:|
| 1200 baud | 6733 ステート |
| 9600 baud | 822 ステート |

したがって、**ボーレートを変えたら一度 `Save` を通してから `Load` する**と
自動的に合う。一度も `Save` していない状態では 1200 baud 固定になる。

### 転送の終わりの判定

**取り込み側**は送り終わりが信号から分からないので、**時間で区切る**。
最後にビットを受けてから `SIO_IDLE_US`（20000usec）だけ何も来なければ
1 回の転送とみなす。1200 baud のビット周期が約 842usec なので 20 ビット分にあたる。
文字と文字の間がこれ以上空くことはない。

判定は `sioPoll()` が 1 フレームに 1 回行う。`out18()` は ROM が書いたときしか
呼ばれないため、無通信の検出をそこでは行えない。

**送出側**はビット列を出し切った時点で終わる。

## ファイルの形式

**受け取ったバイト列をそのまま保存する。** 改行コードや終端コードには手を加えない。
これらは `Format` で変更できる設定なので、加工するとどの設定で保存したのかが
分からなくなるため。

工場出荷時の設定（end of line = CR LF、end of file = 1A、line number = yes）で
`10 ABCDE` の 1 行を送ると、次の 11 バイトになる。

```
31 30 20 41 42 43 44 45 0d 0a 1a
 1  0     A  B  C  D  E CR LF EOF
```

ファイル名は `text.txt` 固定。`BSAVE` と違い、TEXT の `Sio` には名前を指定する
手段がないため。

`Load` では、**末尾が `0x1A` でなければ補う。** 受信側は終端コードを見るまで
待ち続けるため、テキストエディタで作ったファイルをそのまま渡せるようにしてある。
`Format` の `end of file` を既定値から変えている場合は合わない。

## 既存実装からの変更点

もとは `serialcapture()` という関数で、復号したバイトを 1 文字ずつ
`console.log()` に渡していた。このプロジェクトの `console.log` はデバッグ窓
（`<textarea>`）への追記に差し替えられており、1 文字ごとに

- `logger.value +=` で textarea の内容を読み出して連結し書き戻す
- `setSelectionRange()` と `scrollHeight` の参照で同期レイアウトを起こす

を行っていた。`logger.value +=` は毎回全文をコピーするため、
**1 文字あたりのコストが受信済みの文字数に比例して増える**。

実測（Chromium）:

| textarea の既存文字数 | 1 文字あたり |
|--:|--:|
| 0 | 5.0 usec |
| 5,000 | 18.4 usec |
| 20,000 | 32.2 usec |
| 50,000 | 81.6 usec |

しかもこれが `out18()` の中、つまりエミュレーションのループの中で同期的に走る。

書き直したあとは**画面に触らずバイト列に積むだけ**にした。同じ測定条件で
50,000 バイトを流し込んだところ、全体で 4.5 msec、**1 バイトあたり 0.09usec** で、
受信済みの量によらず一定になった。50KB の転送で比べると 2 秒強が 5 ミリ秒未満になる。

あわせて次の 2 点も直した。

- **文字を落とさなくなった。** もとは `0x20` 以上と `0x0A` しか出力しておらず、
  CR（`0x0D`）と終端の `0x1A` が消えていた。上の 11 バイトのうち 2 バイトが
  失われる計算になる
- **`sioEnable` が false のときは即座に戻る。** もとは無効時も毎回
  ビット判定まで進んでいた

進行状況の表示欄は `BSAVE` と共用にした。`bsaveProgress()` は
`transferProgress()` に名前を変え、動いている転送の状況を出す。

## 制約

- **ボーレートを変えたときは一度 `Save` を通す必要がある。** 送出側の周期は
  取り込みの実測から決めているため
- `Format` の設定を読んでいない。`data bit` や `parity` を既定値から変えると
  取り込みも送出も合わなくなる
- 送出中に取り込みを行わない。同じ `0x18` を見ているが、`Load` 中は
  ROM が `0x18` を叩かないため実害はない
- SIO CAPTURE を外した状態で `Save` を実行すると `0x1F` が密に読まれるため、
  送出を予約していると `Load` と誤認して送り始めてしまう
- 送出のたびに `text.txt` がダウンロードされる。同名ファイルの扱いはブラウザ任せ

## 検証

- `10 ABCDE` の 1 行を `Sio` → `Save` で送り、`31 30 20 41 42 43 44 45 0d 0a 1a`
  の 11 バイトが得られることを確認
- 50,000 バイト相当のビット列を `sioCapture()` に流し、全バイトが正しく復号され、
  所要時間が 4.5 msec であることを確認
- `30 HELLO` を送出して `Load` で受け取り、`L`（LIST）で画面に出ることを確認
- 2 行のファイル（`60 FROM FILE` / `70 SECOND LINE`）を **LOAD TXT** から選び、
  `Load` で両方が画面に出ることを確認
- `Format` を 9600 baud にして `Save` すると実測周期が 822 ステートに変わり、
  その周期での `Load` も成功することを確認
- 2 行を `Save` → 21 バイト（`30 HELLO` CR LF `40 WORLD` CR LF EOF）を確認
- `transferProgress()` への改名後も `BSAVE` が動くことを確認
  （`10 REM ZZ` を `BSAVE` して 68 バイト、進行状況の表示も従来どおり）
